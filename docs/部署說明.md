# 部署說明：在自己的帳號架起這套系統

本系統由三部分組成：Notion（資料庫）、Make.com（自動化）、LINE 官方帳號（現場介面）。照下面的順序在自己的帳號建好，就可以跑起來。

## 1. Notion：建立資料庫

- 依 `docs/第一版LINE流程.md` 和畫布 `系統功能架構.excalidraw`，建立 13 張資料表：災害事件、收容所開設、收容所、收容登記、家戶、號碼牌、工作人員名冊、出勤紀錄、進出紀錄、物資品項、物資異動紀錄、現場日誌、問答與公告。
- 欄位名稱要和藍圖裡用到的**一字不差**，例如「簽到代碼」、「派駐開設」、「在所狀態」。
- **建好後鎖定資料表**（資料表右上角「⋯」→「鎖定資料庫」）。Make 依欄位名稱讀寫，欄位一改名就會讀不到；例如把「啟用中」改名後，系統會把所有工作人員判定為未啟用，簽退時回覆「您目前不在班」。鎖定後仍可正常編輯資料列（核准工作人員、勾選啟用中），Make 的寫入也不受影響。要加提示文字請寫在欄位的「說明」，不要寫進名稱。
- 要調整欄位時：先解鎖 → 修改 → 同步修改 `tools/make_blueprints.py` 並更新 Make 情境 → 再鎖回去。
- 取得 7 張表的 **data source ID**（collection ID）：工作人員名冊、收容所開設、出勤紀錄、現場日誌、號碼牌、收容登記、進出紀錄。

> 待補：資料表欄位的完整清單（可以匯出成範本，之後補上）。

## 2. LINE：官方帳號與 Messaging API

1. 建立 LINE 官方帳號，並在 LINE Developers 開啟 Messaging API。
2. 在 Make.com 建立 LINE 連線，用 channel access token。這個 token 只存在 Make.com，不要放進版本庫。
3. 圖文選單由 Make.com 情境「12」建立，不必在 LINE Official Account Manager 設定（見第 4、5 步）。
4. 現場頁面（LIFF，必要）：圖文選單每一格都打開這個頁面的不同畫面。在**同一個 Provider** 底下建立 LINE Login channel，新增 LIFF app（Size：Full；Scope：openid、profile；Scan QR：開啟；Endpoint URL：`https://<GitHub 帳號>.github.io/<repo>/liff/supplies/`），把 channel 狀態改成 Published。記下 LIFF ID 和 Channel ID，填進設定檔的 `line.liff_id`、`line.login_channel_id`，並把 `liff/supplies/app.js` 開頭 `CONFIG` 的 `liffId` 換成你的 LIFF ID。

## 3. Make.com：連線與 webhook

1. 建立 Notion 連線，並把根頁面分享給它。
2. 建立 LINE「Watch Events」webhook，把 webhook 網址貼到 LINE Developers 的 Webhook URL。
3. 記下 webhook 編號、LINE 連線編號、Notion 連線編號，三個都是數字。
4. 物資頁面用：另外建立一個「Custom webhook」（給情境 13），記下編號填進 `make.supply_api_hook_id`，並把它的網址填進 `liff/supplies/app.js` 的 `CONFIG.apiUrl`，同時更新 `index.html` 的 CSP（`connect-src`）裡的網域。這個網址會公開在網頁上；沒有通過 LINE 身分驗證的請求都會被擋下，萬一被濫用可以換一個新網址。
   現場頁面的所有畫面（物資、居民、本所，以及收容所資訊、我要反映、緊急聯絡、工作人員專區、簽退）都用這一個 webhook 和情境 13。Make 免費方案只能啟用兩個情境，第一版只需要啟用 11 和 13。

## 4. 填設定、產生藍圖

```bash
cp tools/config.example.json tools/config.local.json
```

- 編輯 `tools/config.local.json`，填入上面拿到的 ID 和編號。
- 選單圖片：建立一個 Notion 頁面，在頁面裡放**第一組左右兩欄**：左欄放一般選單圖、右欄放加乘選單圖。把頁面 ID 填進 `richmenu_page_id`。系統用每一欄裡**最後一張**圖片。
  - 用預設圖：執行 `python tools/make_richmenu.py`，產生 `assets/richmenu_public.png`、`richmenu_staff.png`。
  - 自己設計：執行 `python tools/make_richmenu.py --template`，產生兩張設計範本，照範本設計 2500 × 1686 px 的圖。
  - 換圖：把新圖放進該欄，取代原本那張，再執行一次情境「12」。一般選單會立刻換掉；加乘選單要等工作人員簽退後重新簽到。

```bash
python tools/make_blueprints.py
```

藍圖會輸出在 `make/`。這個資料夾不進版本庫，因為裡面是你的實際 ID。版本庫裡的 `make/example/` 是用範例設定產生的參考版本。

## 5. 匯入 Make.com

> 用 Make 介面匯入 webhook 觸發的情境（11、13）後，打開情境確認排程仍是「Immediately」。曾發生匯入後變成「每 15 分鐘」，頁面送出的請求只會收到「Accepted」而沒有回應。

1. 在 Make.com 用「Import Blueprint」匯入 `make/12_建立圖文選單.blueprint.json`，執行一次（Run once）。這會建立兩張選單、把一般選單設為預設、設定加乘選單的別名。
2. 匯入 `make/11_LINE訊息_第一版.blueprint.json`，然後啟用。
3. 匯入 `make/13_物資API.blueprint.json`，然後啟用。用手機在 LINE 裡打開 LIFF 網址測試。
4. （選用）匯入 `make/90_清理舊圖文選單.blueprint.json`，維持停用。每次重建選單後執行一次，刪掉不再使用的舊選單（使用中的兩張會保留）。

同一套流程要放到另一個 Make 帳號時，在設定檔的 `make_accounts` 加一組連線編號，執行 `python tools/make_blueprints.py --account <名稱>`，藍圖會輸出到 `make/<名稱>/`。

## 6. 開始使用

1. 工作人員在 LINE 按選單的「工作人員」→「申請開通」。
2. 管理者到 Notion 的工作人員名冊設定角色，勾選「啟用中」。
3. 社會處建立災害事件和收容所開設，填好簽到代碼，印出簽到 QR。QR 格式見 `docs/QR編碼規則.md`。

## 7. 資安設定（弱點掃描前確認）

- **現場頁面**（`liff/supplies/`）：`index.html` 只有版面，程式在 `app.js`；`mock.js` 是本機預覽用的模擬資料，正式網址不會載入。
  - `index.html` 以 `<meta>` 設定內容安全政策（CSP）：程式只能從本站和 LINE 的 CDN 載入，連線只能到 Make webhook 和 LINE。換 webhook 網域時要一起改。
  - LINE SDK 固定版本（`liff/edge/versions/2.31.2/sdk.js`）。LINE 的 CDN 不送 CORS 標頭，無法加子資源完整性（SRI）；SDK 授權不明，不自行託管。
  - 另設 `referrer`（strict-origin-when-cross-origin）、`robots`（noindex）。GitHub Pages 不能自訂回應標頭，`X-Frame-Options`、`frame-ancestors` 等需要換主機或前面加一層 CDN 才能設定。
- **後端**（情境 13）：
  - 先檢查請求格式（有沒有憑證、動作是否認得），不對就直接回 400，不先問 LINE，減少被亂打時消耗的額度。
  - 回應裡的姓名、收容所名稱等自由文字用 `encodeURL` 編碼後才放進 JSON，頁面再解碼（`app.js` 的 `ENC_KEYS`）；名稱裡有引號也不會弄壞回應。
  - 寫入 Notion 的文字有長度上限；類別、嚴重程度、年齡層只接受固定選項，其他值改成預設值，避免在 Notion 新增奇怪的選項。
- **弱點掃描時**：請掃描單位以網頁本體為範圍，後端 webhook 排除或限制次數（每個請求都會消耗 Make 額度）。掃描後可以換一個新的 webhook 網址。
